# Six retrieval exercises

Start in `labs/retrieval/exercises.py`. Do not import the reference answers into your solutions. Implement the documented operation, not special cases for the visible examples. Tests cover important cases, not every possible implementation error.

Use three passes: predict the result; implement and test it; change an assumption and explain the outcome. You need Python functions, loops, dictionaries, and basic arithmetic. No neural-network library is required.

## 1. BM25 term weighting

Implement `tf_weight(tf, length, avg_length, k1=1.2, b=0.75)`:

```text
TF factor = tf * (k1 + 1) / (tf + k1 * (1 - b + b * length / avg_length))
```

This excludes IDF. `tf` and `length` must be integers, not booleans, with `0 <= tf <= length`. The average length must be finite and positive; `k1` finite and nonnegative; `b` finite and between zero and one. Reject invalid inputs with `ValueError`. Return zero for `tf == 0`, including when `k1 == 0`.

At average document length, TF of one gives 1.0. TF of five gives about 1.7742, not 5.0. Predict how doubling document length changes the score. Then test what happens with `b=0`.

```bash
python3 -m labs.retrieval.check --only tf_weight
```

<details><summary>Hint</summary>

Separate length correction from the numerator. Validate inputs first. Check zero TF before dividing. Otherwise, `tf=0, k1=0` produces an avoidable zero denominator.

</details>

## 2. Sparse scoring

Implement `sparse_dot(query, doc)` for dictionaries with vocabulary-token keys and finite numeric weights. For this exercise inputs satisfy that type contract; no extra validation is required. Missing coordinates have weight zero. Empty inputs score zero. Do not multiply different coordinates together.

```text
query = {car: 1.5, automobile: 0.7, repair: 1.3, maintenance: 0.9}
doc   = {automobile: 1.4, repair: 0.8, maintenance: 1.2}
score = 0.7*1.4 + 1.3*0.8 + 0.9*1.2 = 3.10
```

These weights were chosen for the exercise, not generated by SPLADE. Semantic expansion would be the encoder's job. Your function only scores its output.

```bash
python3 -m labs.retrieval.check --only sparse_dot
```

<details><summary>Hint</summary>

Iterate over query items. Look up the same key in the document with a default of zero. Then compare this implementation with `sparse_index_scores` in the reference. The index is another way to execute the same score.

</details>

## 3. MaxSim and padding

Implement `maxsim(matrix, valid_doc=None)`. Rows are query vectors. Columns are document vectors. For each row, take the maximum over valid document positions; then add the row maxima. A supplied Boolean mask has one entry per column. With no mask, every column is valid.

Raise `ValueError` for an empty matrix, an empty row, ragged rows, non-finite numbers, a mask of the wrong length, or a mask that excludes every document position. Numeric type validation beyond this contract is not required.

```text
[[0.9, 0.1, 0.0],
 [0.1, 0.8, 0.2]] -> 1.7

[[-0.2, -0.5, 0.0]], mask=[True, True, False] -> -0.2
```

The second example is the trap. Zero is larger than the valid negative similarities. Mask before taking the maximum. Predict whether duplicating a matrix column changes the answer. This question fixes the vectors; it does not assume that editing text leaves embeddings unchanged.

```bash
python3 -m labs.retrieval.check --only maxsim
```

<details><summary>Hint</summary>

Select valid entries before reducing each row. Do not calculate the unmasked maximum and then try to correct it afterward. Query augmentation positions in actual ColBERT are a separate model-specific issue; this exercise only masks document columns.

</details>

## 4. Reciprocal Rank Fusion

Implement `rrf(rankings, c=60)`. Each input is a ranked list of document IDs. Ranks start at one. A document receives `1 / (c + rank)` from each list that contains it. A missing document contributes zero.

Reject duplicates within one list. The same ID in different lists is expected. Reject negative or non-finite `c`. Return `(document_id, score)` pairs sorted by descending score, then alphabetical ID to resolve ties. Empty lists contribute nothing.

For `[A, B]` and `[C, B]`, B should finish first with `2/62`. The constant 60 is not the number of documents being retrieved.

```bash
python3 -m labs.retrieval.check --only rrf
```

<details><summary>Hint</summary>

Accumulate into a dictionary. Use one-based enumeration. Sum rank contributions, not the raw scores of the underlying retrieval methods.

</details>

## 5. Recall is not Hit@K

Implement `recall_at_k(relevant, ranking, k)`. Divide the number of unique relevant IDs in the first `k` ranking positions by the size of the relevant set. Duplicates occupy positions but count once. `k` must be an integer, not a boolean, and nonnegative. `k=0` gives zero. Larger `k` than the list length is allowed.

An empty relevant set makes this form of recall undefined. Raise `ValueError`. Unanswerable queries need a separately stated evaluation rule.

```text
relevant = {A, B, C, D}
ranking  = [X, A, Y]
Recall@3 = 0.25
Hit@3    = 1
```

```bash
python3 -m labs.retrieval.check --only recall_at_k
```

<details><summary>Hint</summary>

Slice by ranking position before taking the set intersection. Deduplicating the whole ranking first changes which documents appear within the top K.

</details>

## 6. Candidate selection can miss the aggregate winner

Implement `candidate_union(matrices, per_query=1)`. Input maps document IDs to similarity matrices. Each matrix has the same number of query rows but may have a different document-token count. For each query row, score each document by its best token similarity. Select the `per_query` best documents and union their IDs. Break ties alphabetically.

Require a positive integer `per_query` (not a boolean), finite rectangular nonempty matrices, and consistent query-row counts. Empty document maps return an empty set. `per_query` greater than the number of documents is allowed. Raise `ValueError` for invalid inputs.

```text
A: [[0.95],       [0.05]]       MaxSim = 1.00
B: [[0.05],       [0.95]]       MaxSim = 1.00
C: [[0.80, 0.00], [0.00, 0.80]] MaxSim = 1.60
```

At `per_query=1`, your result should contain A and B, not C. At two it should include all three. This is a deliberately small screening rule, not an implementation of PLAID or an approximate token index.

```bash
python3 -m labs.retrieval.check --only candidate_union
```

<details><summary>Hint</summary>

Do not rank by the summed MaxSim score during screening; that would solve a different problem and hide the failure case. Score and sort documents independently for each query row.

</details>

## After the checks pass

Write one new test and explain what assumption it challenges. Examples: a misleading repeated term; three query conditions where one fails but the sum still wins; an RRF consensus that promotes the wrong result. Label constructed examples as constructed.

The most confusing boundary is **the model's score versus the search procedure's candidate set**. Both can be wrong. Widening the candidate set and changing the score are different interventions.
